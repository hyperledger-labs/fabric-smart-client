# Upgrading from v0.28 to v0.29

This guide takes an application built on Fabric Smart Client (FSC) v0.28.0 to
v0.29.0. Coming from an older release, first follow
[v0.27-to-v0.28.md](v0.27-to-v0.28.md).

v0.29 makes websocket P2P TLS strict about its configuration and accepts
identity certificates without SANs, applies `logging.otel.sanitize` to every
logger, and keeps a node from exiting from inside FSC when a server fails to
start. The Fabric-x ledger fails over to another committer. No FSC store gains a
schema step, so a node rolls back to v0.28 by running the v0.28 binary on the
same database. Whether a node's replicas can run v0.28 and v0.29 side by side is
given by `upgrade.mode` in the release data of v0.29.0 (see
[Rolling upgrades](rolling-upgrade.md)).

Organizations can upgrade independently. A v0.28 node still fails to dial a peer
whose identity certificate has no SANs, so an organization that issues such
certificates waits until every node that dials it runs v0.29 (see
[WebSocket P2P TLS](#websocket-p2p-tls)). [Ordering](#ordering) and the
[Fabric API](#fabric-api) changes apply to Fabric only;
[Fabric-x committers](#fabric-x-committers) and the
[Fabric-x API](#fabric-x-api) changes apply to Fabric-x only.

## For operators

### WebSocket P2P TLS

**Applies to:** Every node with `fsc.p2p.type: websocket`.

- During the TLS handshake, a node verifies the certificate chain of the peer it
  dials and checks that the certificate's key belongs to the peer ID it dialed.
  It does not match a host name. A v0.29 node therefore dials a peer whose
  identity certificate has no SANs, where a v0.28 node fails with
  `x509: certificate is not valid for any names`. A deployment that patched
  `InsecureSkipVerify` into the websocket client to get past that error should
  drop the patch: it also turns off chain verification. See
  [WebSocket](../platform/view/services/comm/websocket.md#protocol-handshake-and-upgrading).
- `fsc.p2p.opts.websocket.tls.serverNameOverride` takes effect: it is the SNI
  name of every outbound websocket connection, including those
  `node peers --check` opens. In v0.28 the key was accepted but had no effect,
  and nodes sent the host of the dialed address, or no SNI for an IP address. A
  node that sets it sends a different SNI name after the upgrade, which matters
  behind a proxy that routes on SNI. Remove the key to keep sending the dialed
  host.
- Under `fsc.p2p.opts.websocket.tls`, a node fails to start when `enabled`,
  `clientAuthRequired` or `clientAuthEnabled` is `false`, or when `cert` or
  `clientCert` names a certificate other than `fsc.identity.cert.file`. The
  error names the key. Websocket P2P always runs mutual TLS with the identity
  keypair. In v0.28 `enabled: false` was ignored and the node ran TLS anyway;
  the other settings failed at startup with a misleading error, or let the node
  start but fail every session on the peer ID check. Remove these keys, or set
  the flags to `true` and the files to the identity keypair.

### Logging

**Applies to:** Every node.

- With `logging.otel.sanitize: true`, the setting applies to span events from
  every logger: non-printable characters are removed from the event name, which
  then starts with `[nonprintable]` followed by a space. In v0.28 it reached
  only loggers created after the node read its configuration, which excludes
  most of FSC's loggers, so their span events kept the raw message. Update trace
  queries and alerts that match such event names.
- Debug lines no longer print ledger values, read-write sets or transactions in
  full; they print `logging.SHA256Base64` of the value, or a count. The errors
  of `Idemix.DeserializeAuditInfo`, `Transaction.SetFromBytes` and the state
  service's namespace helpers carry the hash instead of the value, and the
  hash-mismatch error no longer carries the preimage. A procedure that reads
  state values from debug logs needs another source.
- A logger derived with `Named` or `With` reports the caller of the log call. In
  v0.28 it reported a frame one level too high. Log queries that match on the
  caller field see different values.

### Startup and server failures

**Applies to:** Every node.

- A node whose web server, metrics server (`fsc.metrics.address`) or metrics
  system (`fsc.metrics.provider`) fails to start, for example on a port in use,
  no longer exits from inside FSC: `node start` reports the error and exits
  after releasing the listeners, the P2P host and the KVS.
- When `fsc.grpc` stops serving on an error while the node runs, the node logs
  `grpc server stopped serving, the node reports not ready` at Error, and
  `GET /readyz` answers 503 with the body
  `{"status":"not ready","reason":"grpc server stopped"}`, which takes the node
  out of rotation. The node keeps running without `fsc.grpc` and `/healthz`
  stays 200, so a liveness probe does not restart it: alert on the log line or
  the `/readyz` reason, and restart the node.

### Ordering

**Applies to:** Every node with a Fabric network.

- A node whose `fabric.<network>.ordering.connectionPoolSize` is `0` or negative
  logs `invalid ordering.connectionPoolSize` as a warning and uses 10, the
  default. In v0.28 the BFT broadcaster panicked, and the CFT broadcaster
  panicked or blocked every broadcast. Set a positive value, or remove the key
  to use the default.

### Fabric-x committers

**Applies to:** Every node with a Fabric-x network.

- The ledger (`GetBlockByNumber`, `GetBlockNumberByTxID`, `GetTransactionByID`,
  `GetLedgerInfo`) uses every committer endpoint of the network. A call that
  fails with `Unavailable` is retried once on another endpoint. In v0.28 the
  ledger kept calling the committer it first connected to, even after that
  committer went down.
- While a node's notification stream is down, and once a new stream is up, the
  node asks the query service for the status of the transactions whose finality
  it waits for. A transaction that committed during the outage is settled at
  once, instead of after the committer's request timeout, 30s by default, on the
  next stream. Each failed stream or connection attempt adds one query for the
  pending transactions.

## For developers

### Fabric API

- `core.FSNProvider.InitFabricLogging` is removed.
  `NewFabricNetworkServiceProvider` no longer initializes logging:
  `config.NewProvider` applies `logging.format` and `logging.spec` once, and a
  writer or spec the application sets with `logging.Init` stays in place. Delete
  any call to `InitFabricLogging`; call `logging.Init` to change the logging
  configuration.
- A configuration built with `config.Provider.ProvideFromRaw` does not
  initialize logging, even when it enables a Fabric network. Call `logging.Init`
  with its `logging.*` values yourself.
- The package `platform/fabric/core/msp/mgmt` is removed; no FSC code used it.
- New: an error of the view `NewCollectEndorsementsView` returns can be matched
  with `errors.Is`. A rejection wraps `session.ErrRejected` and the reason's
  sentinel, such as `session.ErrDraining`; a closed session wraps
  `comm.ErrSessionClosed`; the timeout wraps `context.DeadlineExceeded`. The
  error text is unchanged. See
  [Collecting endorsements](../platform/fabric/fabric-sdk.md#collecting-endorsements).

### Fabric-x API

- `config.ClientProvider.NotificationServiceClient` and the `GRPCClientProvider`
  interfaces of `platform/fabricx/core/ledger` and
  `platform/fabricx/core/finality` take a second argument `skip`, the endpoint
  to avoid; pass `""` to skip nothing. Regenerate counterfeiter mocks of both
  `GRPCClientProvider` interfaces.
- The ledger picks a committer connection on every call and retries a call that
  fails with `Unavailable` once on another endpoint.
  `ledger.NewWithClientFactory` takes a client factory
  `func(skip string) (committerpb.SidecarServiceClient, string, error)` for
  this; `ledger.New` keeps making every call on the one client it is given.

### View SDK

- `SDK.Start` of the view SDK returns an error when the web server, the metrics
  server or the metrics system (`operations.System`) fails to start, and
  releases the gRPC listener, the P2P host and the KVS. The process no longer
  exits; `Node.Start` returns the error, and the application handles it.
- A `WebServer` that replaces the default must return from `Start` once it
  serves; the SDK calls it inline. A `GRPCServer` that replaces the default
  keeps serving in `Start` until `Stop`.
- `sdk.Serve` in `platform/view/sdk/dig` is removed. Start the servers with the
  SDK.
- New: `viewsdk.ReadinessGateEntry` provides a `web.ReadinessGate` into the dig
  group `fsc-readiness-gates`. While such a gate is not ready, `GET /readyz`
  answers 503 with its reason, after `draining`, `migrating` and
  `grpc server stopped`. Without one, `/readyz` answers as in v0.28.

## Checklist

Operators:

- WebSocket P2P: drop any local patch that sets `InsecureSkipVerify` in the
  websocket client. Issue identity certificates without SANs only once every
  node that dials them runs v0.29.
- WebSocket P2P: if `fsc.p2p.opts.websocket.tls.serverNameOverride` is set,
  check that every peer, and any SNI-routing proxy in front of it, accepts that
  name; remove the key to keep sending the dialed host.
- WebSocket P2P: remove `enabled: false`, `clientAuthRequired: false`,
  `clientAuthEnabled: false`, and any `cert`/`key` or `clientCert`/`clientKey`
  that is not the `fsc.identity` keypair, from `fsc.p2p.opts.websocket.tls`.
- Logging: with `logging.otel.sanitize: true`, update trace queries and alerts
  that match span event names containing non-printable characters. Stop relying
  on debug logs for state values.
- Alert on the `/readyz` reason `grpc server stopped`, or on its log line, and
  restart the node when it appears.
- Fabric: set `fabric.<network>.ordering.connectionPoolSize` to a positive
  value, or remove it.

Developers:

- Fabric: delete calls to `FSNProvider.InitFabricLogging`. An application that
  builds its configuration with `ProvideFromRaw` calls `logging.Init` itself.
- Drop uses of `sdk.Serve` and `platform/fabric/core/msp/mgmt`.
- Handle the error `Node.Start` returns when a server fails to start.
- A replaced `WebServer` returns from `Start` once it serves; a replaced
  `GRPCServer` serves in `Start` until `Stop`.
- Fabric-x: pass the new `skip` argument to `NotificationServiceClient`, and
  regenerate counterfeiter mocks of the `GRPCClientProvider` interfaces of
  `ledger` and `finality`.
