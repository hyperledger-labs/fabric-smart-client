# Upgrading from v0.28 to v0.29

This guide takes an application built on Fabric Smart Client (FSC) v0.28.0 to v0.29.0. Coming from an older release, first follow [v0.27-to-v0.28.md](v0.27-to-v0.28.md).

Organizations can upgrade independently. The [Fabric-x API](#fabric-x-api) changes apply to Fabric-x only.

# For operators

## WebSocket P2P TLS

**Applies to:** Every node with `fsc.p2p.type: websocket`.

- A node verifies the chain of a peer's certificate and binds it to the peer ID it dialed, both
  during the TLS handshake, but matches no host name in it. Identity certificates without SANs
  therefore work, and a node no longer fails to dial such a peer with `x509: certificate is not
  valid for any names`. A deployment that patched `InsecureSkipVerify` into the websocket client
  to get past that error should drop the patch: it also turns off chain verification. See
  [WebSocket](../platform/view/services/comm/websocket.md#protocol-handshake-and-upgrading).
- `fsc.p2p.opts.websocket.tls.serverNameOverride` takes effect: it is the SNI name of every
  outbound websocket connection, including those `node peers --check` opens. In v0.28 the key
  was accepted but had no effect, and nodes sent the host of the dialed address, or no SNI for
  an IP address. A node that sets it sends a different SNI name after the upgrade, which matters
  behind a proxy that routes on SNI. Remove the key to keep sending the dialed host.
- Under `fsc.p2p.opts.websocket.tls`, a node fails to start when `enabled`,
  `clientAuthRequired` or `clientAuthEnabled` is `false`, or when `cert` or `clientCert` names a
  certificate other than `fsc.identity.cert.file`. The error names the key. Websocket P2P always
  runs mutual TLS with the identity keypair. In v0.28 `enabled: false` was ignored and the node
  ran TLS anyway; the other settings failed at startup with a misleading error, or let the node
  start but fail every session on the peer ID check. Remove these keys, or set the flags to
  `true` and the files to the identity keypair.

## Logging

**Applies to:** Every node with `logging.otel.sanitize: true`.

- The setting applies to span events from every logger: non-printable characters are removed
  from the event name, which then starts with `[nonprintable] `. In v0.28 it reached only
  loggers created after the node read its configuration, which excludes most of FSC's loggers,
  so their span events kept the raw message. Update trace queries and alerts that match such
  event names.

## Startup and server failures

**Applies to:** Every node.

- A node whose web server, metrics server (`fsc.metrics.address`) or operations system fails to
  start, for example on a port in use, no longer exits from inside FSC: `node start` reports the
  error and exits after releasing the listeners, the P2P host and the KVS.
- When `fsc.grpc` stops serving on an error while the node runs, the node logs it at Error and
  `/readyz` answers 503 with reason `grpc server stopped`, which takes the node out of rotation.
  The node keeps running without `fsc.grpc` and `/healthz` stays 200, so a liveness probe does not
  restart it: alert on the reason, or restart the node.

# For developers

## Fabric API

- `core.FSNProvider.InitFabricLogging` is removed. `NewFabricNetworkServiceProvider` no longer
  initializes logging: `config.NewProvider` applies `logging.format` and `logging.spec` once, and
  a writer or spec the application sets with `logging.Init` stays in place. Delete any call to
  `InitFabricLogging`; call `logging.Init` to change the logging configuration.
- A configuration built with `config.Provider.ProvideFromRaw` does not initialize logging, even
  when it enables a Fabric network. Call `logging.Init` with its `logging.*` values yourself.

## Fabric-x API

- `config.ClientProvider.NotificationServiceClient` and the `GRPCClientProvider` interfaces of
  `platform/fabricx/core/ledger` and `platform/fabricx/core/finality` take a second argument
  `skip`, the target to avoid; pass `""` to skip nothing. Regenerate counterfeiter mocks of both
  `GRPCClientProvider` interfaces.
- The ledger picks a committer connection on every call and retries a call that fails with
  `Unavailable` once on another endpoint. `ledger.NewWithClientFactory` takes a client factory
  `func(skip string) (committerpb.SidecarServiceClient, string, error)` for this; `ledger.New`
  keeps making every call on the one client it is given.

## View API

- New: `viewsdk.ReadinessGateEntry` provides a `web.ReadinessGate` into the dig group
  `fsc-readiness-gates`. While such a gate is not ready, `GET /readyz` answers 503 with its
  reason, after `draining`, `migrating` and `grpc server stopped`. Without one, `/readyz` answers as in v0.28.

## Node startup

- `SDK.Start` of the view SDK returns an error when the web server, the metrics server or the
  operations system fails to start, and releases the gRPC listener, the P2P host and the KVS.
  The process no longer exits; `Node.Start` returns the error.
- A `WebServer` that replaces the default must return from `Start` once it serves; the SDK calls it
  inline. A replaced `GRPCServer` keeps serving in `Start` until `Stop`.
- `sdk.Serve` in `platform/view/sdk/dig` is removed. Start the servers with the SDK.
- The package `platform/fabric/core/msp/mgmt` is removed; no FSC code used it.

# Checklist

Operators:

- WebSocket P2P: drop any local patch that sets `InsecureSkipVerify` in the websocket client. If
  `fsc.p2p.opts.websocket.tls.serverNameOverride` is set, check that every peer, and any
  SNI-routing proxy in front of it, accepts that name; remove the key to keep sending the dialed
  host.
- WebSocket P2P: remove `enabled: false`, `clientAuthRequired: false`, `clientAuthEnabled: false`,
  and any `cert`/`key` or `clientCert`/`clientKey` that is not the `fsc.identity` keypair, from
  `fsc.p2p.opts.websocket.tls`.
- Logging: with `logging.otel.sanitize: true`, update trace queries and alerts that match span
  event names containing non-printable characters.
- Alert on `/readyz` reason `grpc server stopped`, or restart the node when it appears.

Developers:

- Fabric: delete calls to `FSNProvider.InitFabricLogging`; a node built from `ProvideFromRaw`
  calls `logging.Init` itself.
- Drop uses of `sdk.Serve` and `platform/fabric/core/msp/mgmt`.
- A replaced `WebServer` returns from `Start` once it serves.
- Fabric-x: pass the new `skip` argument to `NotificationServiceClient`, and regenerate
  counterfeiter mocks of the `GRPCClientProvider` interfaces of `ledger` and `finality`.
