# Upgrading from v0.29 to v0.30

This guide takes an application built on Fabric Smart Client (FSC) v0.29.0 to
v0.30.0. Coming from an older release, first follow
[v0.28-to-v0.29.md](v0.28-to-v0.29.md).

v0.30 supports only version 2 of the `fabric` and `fabricx` wire formats, and
refuses a session with a node that has no common version of a component,
whichever node opens it, before its view runs. Nodes of v0.27 and older support
only version 1, so v0.30 refuses them.

v0.30 also freezes the logging API that v1 keeps: `logging.Logger` exposes no
zap type, and `logging.Init` returns an error instead of panicking. A node with
an invalid logging configuration fails to start with an error that names the
key, and each logger is checked against its own level in `logging.spec`.

Organizations can upgrade independently: v0.28 and v0.29 support versions 1 and
2, so their nodes and v0.30 nodes use version 2. Every node that talks to a
v0.30 node must run v0.28 or later.

v0.30 also opens the endorse-tx store and the vault only once their contract
step 2 has run, and writes only protobuf to them.

## Toolchain and dependencies

|     | v0.29  | v0.30  | Platform   |
| --- | ------ | ------ | ---------- |
| Go  | 1.27.3 | 1.27.4 | Every node |

- Every FSC module declares `go 1.27.4`, the release that fixes GO-2026-6859 in
  `net/http`. Adding FSC v0.30 to a module raises the `go` line of its `go.mod`
  to at least 1.27.4. A build that sets `GOTOOLCHAIN=local` or uses a pinned Go
  image needs Go 1.27.4 installed first.

## For operators

### Peers of v0.27 and older

**Applies to:** Every node with a peer that runs FSC v0.27 or older.

- A v0.30 node and a node of v0.27 or older refuse each other's sessions, for
  every view. A v0.27 initiator gets the error
  `no_common_version: fabric 1 not in [2, 2]`. A v0.30 initiator fails with
  `component [fabric]: local [2, 2], peer [1, 1]: no common version` and sends
  nothing. In v0.29, which supports versions 1 and 2, these sessions ran.

### Peers without a common version

**Applies to:** Every node that runs `node peers --check`.

- `node peers --check` counts every component of a peer without a preamble, and
  a component a peer does not announce, as version 1, and exits 11 if that is
  outside the range of the binary. For such peers v0.29 printed the ranges and
  exited 0.

### Logging

**Applies to:** Every node.

- A node with an invalid `logging.spec` or `logging.format` fails to start with
  an error that names the key, or `FABRIC_LOGGING_SPEC` when the spec comes from
  that variable. In v0.29 it panicked. A spec is invalid with an unknown level
  or a malformed logger name, a format with an unknown `%{color:...}` option; an
  unknown `%{verb}` is printed as text.
- `logging.spec` is matched per logger name for every level check. In v0.29 a
  spec that set one logger to `debug` made every logger build its debug lines
  before dropping them, which cost CPU on a busy node.
- The gRPC server of the node (`fsc.grpc`) logs one line per call at Debug,
  under the logger `fsc.platform.view.sdk.dig`. The `payload` child logger,
  which logged request and response messages at the `payload` level, is gone.
- At startup the node logs one Info line with the logging spec and the handler,
  under the logger `fsc.platform.common.services.logging`.

### Contract steps of the endorse-tx store and the vault

**Applies to:** Every node whose endorse-tx store or vault on SQLite or Postgres
has contract step 2 pending. That is a database that FSC v0.27 or older created
and on which nobody ran `node migrate --contract` since. A store that v0.28 or
v0.29 created ran the step at once.

- v0.30 refuses to start on such a store with an error that ends in
  `required contract step has not run; run node migrate --contract`.
  `node migrate` and `node migrate --check` exit 10 on it.
- Run `node migrate --contract` before rolling out v0.30, with v0.28, v0.29 or
  v0.30: all three know the step. It exits 12 while the openers table records a
  binary that lacks the step; add `--forget-opener <fsc.id>` for each listed
  node none of whose replicas runs v0.27 or older anymore (see
  [Contract steps](../platform/view/services/schema-migrations.md#contract-steps)).
  On a large store, run it in a maintenance window.
- The vault refuses to write metadata whose key is not valid UTF-8, with an
  error that names the namespace, the key and the metadata key. v0.29 stored such
  metadata gob-encoded. A committed Fabric transaction cannot carry such a key.

## For developers

### Storage API

- `migrate.ReadableByObserver` is gone. A store that needs a contract step to
  have run marks the step `Required` (see
  [Schema versioning](../platform/view/services/schema-versioning.md#contract-steps));
  `Migrate` then refuses the store while the step is pending.

### View API

- On a session the node opens, `Send` and `SendError` fail with
  `view.ErrNoCommonVersion`, naming the component and both ranges, when any
  component has no common version with the peer, and write nothing. In v0.29
  they sent the message with version 0 stated for that component, and only a
  codec that read the version first failed.
- A responder counts a component that a first message does not state as version
  1 and rejects the message with `no_common_version` if version 1 is outside its
  range. In v0.29 it checked only the stated components. This refuses an
  initiator older than a component an application registers with a minimum above
  1.

### Fabric API

- Transactions and endorsement responses go out as protobuf, a
  `TransactionEnvelope` and an `EndorsementResponse`, on every session, also one
  that is not an FSC network session, such as an in-process one. Receivers still
  read the JSON forms of version 1. A transaction type that adds JSON fields of
  its own to FSC's fails to send on every session; v0.29 already failed to send
  it to v0.28 and v0.29 peers, and sent it as JSON only to peers of v0.27 and
  older and on sessions that are not FSC network sessions.
- `endorser.WireBytes(tx, raw)` takes no context and no session: the form
  depends only on whether the driver of the network registers a transaction
  format. A network whose driver registers none still sends and answers JSON.

### Logging API

`logging.Logger` in `platform/common/services/logging` exposes no zap type, and
is the API v1 keeps. Code that only calls its printf-style methods and the
`*Context` methods other than `PanicfContext` and `PanicwContext` needs no
change.

| v0.29 | v0.30 |
| --- | --- |
| `IsEnabledFor(zapcore.DebugLevel)` | `IsEnabledFor(logging.DebugLevel)`; `logging.Level` is `slog.Level`, whose values differ from zap's, so map each constant instead of converting a zap level |
| `Warningf` | `Warnf` |
| `Fatal`, `Fatalf` | Return an error |
| `Panic`, `Panicf`, `PanicfContext`, `PanicwContext` | Log at Error and return an error; call `panic` for a broken invariant |
| `Zap()` | Use the `Logger` methods |
| `logging.Init(c)` | `if err := logging.Init(c); err != nil { ... }` |
| `GetPackageName`, `NewOtelLogger`, `Replacers`, `OtelSanitize`, the function `ContextLogFields`, `FilterPrintable`, `FilterPrintableWithMarker` | Removed from the API |
| `NewTestLogger(t, options...)`, `logging.Option` | `NewTestLogger(t)`; the logger records every level |
| `Recorder` methods other than `Entries`, `Messages` and `Reset` (`EntriesContaining`, `Buffer` and the others of `floggingtest.Recorder`) | Filter `Entries()` or `Messages()`, e.g. with `slices.ContainsFunc` and `strings.Contains` |

- `Debugw` and `Infow` are new, and every level has `*w` and `*wContext`
  methods. Their first argument is the message.
- `Init` returns an error for an invalid spec or format, and then changes
  nothing. A `Config` with a nil `Writer` keeps the current writer; pass
  `os.Stderr` to reset it. An empty `LogSpec` or `Format` still means the
  default, so to change only the writer, pass the whole configuration again.
  `config.NewProvider` no longer resets the writer, so a writer an application
  sets with `logging.Init` before building the node stays in place.
- `GetLogger` names the logger after the package of its caller. In v0.29 it took
  the package of its caller's caller; `MustGetLogger` is unchanged.
- `Base64`, `SHA256Base64`, `Identifier`, `Eval` and `Since` return
  `fmt.Stringer`. The values of all the lazy helpers are also `slog.LogValuer`s,
  and `SHA256Base64` hashes when the line is formatted, so its argument must not
  change until then.
- `logging.SetHandler` sends every FSC log line to an application's
  `slog.Handler`, and `logging.Handler(name)` routes `slog` lines through
  `logging.spec`; see
  [Logging through the application's handler](../configuration.md#logging-through-the-applications-handler).
- `Init` logs one Info line; a test that checks the output right after `Init`
  must allow for it.
- `Debug`, `Info`, `Warn` and `Error` check the level before they format their
  arguments, so a wrapper that calls `IsEnabledFor` first only to avoid that
  cost can go.
- `UnaryServerInterceptor` and `StreamServerInterceptor` of
  `platform/common/services/grpc/logging` take a `logging.Logger`. `Leveler`,
  `PayloadLeveler`, `LevelerFunc`, `DefaultPayloadLevel`, `Option`,
  `WithLeveler`, `WithPayloadLeveler`, `WithFields`, `ProtoMessage` and `Error`
  are removed.
- `MockLogger` implements the new interface, and its `*w` methods print
  `key=value` pairs. A test type that embeds it and defines `Warningf`,
  `Fatal*`, `Panic*` or `Zap` still compiles, but nothing calls those methods
  any more.

## Checklist

Operators:

- Upgrade every peer of v0.27 or older to v0.28 or later first: run
  `node peers --check` with the v0.30 binary, which exits 11 while such a peer
  remains.
- Treat exit code 11 of `node peers --check` for a peer without a preamble as a
  peer the node can no longer talk to.
- Logging: check that `logging.spec`, `logging.format` and any
  `FABRIC_LOGGING_SPEC` are valid; a node with an invalid value no longer
  starts.
- Run `node migrate --check` with the v0.30 binary; if it exits 10, run
  `node migrate --contract` before the upgrade.

Developers:

- Build with Go 1.27.4 or later.
- Drop the context and session arguments of calls to `endorser.WireBytes`.
- Replace an implementation of `migrate.ReadableByObserver` by `Required: true`
  on the contract step the store depends on.
- Handle `view.ErrNoCommonVersion` from `Send` on sessions to peers that may
  lack a common version of a component the application registers.
- Logging: replace `zapcore.DebugLevel` with `logging.DebugLevel`, `Warningf`
  with `Warnf`, and calls to `Fatal*`, `Panic*` and `Zap()`; check the error of
  `logging.Init`; call `NewTestLogger(t)` without options and filter
  `Recorder.Entries()` instead of calling `EntriesContaining`.
