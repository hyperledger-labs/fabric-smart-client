# Upgrading from v0.13 to v0.26

This guide takes an application built on Fabric Smart Client (FSC) v0.13.0 to v0.26.0, the
latest release. It has two parts: [operators](#for-operators) (configuration, storage, network
behaviour, monitoring) and [developers](#for-developers) (Go API).

You can go straight from v0.13 to v0.26. No intermediate release needs to run first, and the
only data migration (the [Postgres vault](#postgres-vault)) happens automatically on first start.

Expect the upgrade to fail loudly. From v0.21 on, FSC refuses to start on configuration that
older versions accepted and then ignored, misread or replaced with a default, and the startup
error names the key and, for a renamed key, its replacement. On the Go side, most changes are
compile errors. The practical approach is:

1. Bump the dependency and fix compile errors (see [For developers](#for-developers)).
2. Start one node against a copy of the production `core.yaml` in staging and fix each startup
   error it reports.
3. Update the clients that call views on the node and the monitoring that scrapes it.

The per-release details are in the
[GitHub release notes](https://github.com/hyperledger-labs/fabric-smart-client/releases).

## Platforms

Every section starts with an **Applies to** line naming one of these scopes:

| Scope | Meaning |
| --- | --- |
| **Every node** | The FSC node itself: views, P2P, the web and gRPC listeners, monitoring, KVS and identity storage. Applies whatever network the node connects to. |
| **Fabric and Fabric-x** | The Fabric driver code and the `fabric.<network>` configuration that both platforms share: network TLS, `peers`, `ordering`, `mspCacheSize`, `channels`, the endorser and state services. A Fabric-x deployment cannot skip these. |
| **Fabric only** | Parts that only the Fabric platform uses: the Fabric vault store, block delivery and commit pipeline, discovery, chaincode. |
| **Fabric-x only** | The Fabric-x committer integration: query and notification services, the Fabric-x vault, ledger and finality. |

What to read:

| You run | Read sections marked |
| --- | --- |
| Fabric | Every node, Fabric and Fabric-x, Fabric only |
| Fabric-x | Every node, Fabric and Fabric-x, Fabric-x only |

Mixed tables have a **Platform** column with the same scopes.

## Before you start

| Step | Platform |
| --- | --- |
| Back up every database the node uses (KVS, vault, endpoint bindings). This matters most for a Postgres vault, which the first start rewrites. | Every node |
| Plan to stop every replica of a node before starting v0.26. Do not run old and new replicas against the same database. | Every node |
| Find every process that calls views on the node, in particular over REST (`PUT /v1/Views/{View}`, `GET /v1/Views/Stream/{View}`). Those endpoints are gone, and these clients must move to the FSC view client together with the node. | Every node |
| Check the clocks of those callers. The node rejects signed commands whose timestamp is too far from its own clock. | Every node |
| Decide how Prometheus scrapes `/metrics`: with a client certificate, or with `fsc.metrics.clientAuthRequired: false`. | Every node |
| Upgrade every FSC node that talks to another over P2P in the same window. Mixed versions are not tested, and several P2P checks (TLS 1.3 on websocket clients, peer identity binding, message size limits) are stricter on new nodes. | Every node |
| Upgrade the committer to v1.0.7 or later, and register the X.509 signing certificate of every FSC node as a known certificate in the channel configuration (see [Fabric-x](#fabric-x)). | Fabric-x only |

# For operators

## Postgres vault

**Applies to:** Fabric only. The Fabric-x vault keeps no local state table.

On first start, FSC converts the `pkey` column of the Postgres vault's state table from `TEXT`
to `BYTEA`. With `TEXT`, distinct binary keys could collapse onto one row and range scans could
miss children.

- Stop every replica before the upgrade. An older FSC still starts against the converted table,
  but the keys it writes are invisible to v0.26.
- Downgrading requires restoring the backup taken before the upgrade.
- A key that contains a literal `?0?` or `?1?` is converted as if it were an escape sequence.

SQLite deployments are not affected.

## Postgres TLS

**Applies to:** Every node.

Postgres connections can use TLS through a `tls` block in the persistence configuration (see
[Persistence](../configuration.md#persistence-sqlitepostgres)). An empty `ssl_mode` means
`verify-full`, which is stricter than libpq's `prefer`. The block is optional; without
`tls.enabled: true` the `dataSource` is used as is.

## Remote view API

**Applies to:** Every node.

The remote view API is the interface through which other processes call views on the node. In
v0.26 it has its own configuration block, `fsc.view.remote`, and is off unless that block
enables it. A node that serves views to other processes must add it. Views called from inside
the node are unaffected.

```yaml
fsc:
  view:
    remote:
      enabled: true
      # grpc: the fsc.grpc listener; web: the HTTP binding on fsc.web
      backends: [grpc]
      timeout: 2m
      timeWindow: 15m
      clients:
      - path/to/client-cert.pem
```

| v0.13 key | v0.26 key |
| --- | --- |
| `fsc.client.certs` | `fsc.view.remote.clients` |
| none | `fsc.view.remote.timeout` (default `2m`) |
| none | `fsc.view.remote.timeWindow` (default `15m`) |
| none | `fsc.view.remote.maxMessageSize` (optional) |

`fsc.web.viewTimeout` and `fsc.grpc.authentication.timeWindow` existed in v0.25 only and moved
into this block in v0.26. All three old keys fail startup with an error naming the new one.

What changes for callers:

- Every command must be signed, and it is accepted only once and only if its timestamp is within
  `timeWindow` of the node's clock. Clients must sign a fresh command for every call. The replay
  cache is in process memory, so it does not cover a restarted node or a second node serving the
  same identities.
- The node accepts commands signed by its own identity (`fsc.identity`) or by one listed in
  `fsc.view.remote.clients`.
- `timeout` bounds every view call, gRPC and HTTP. A view that runs longer ends with
  `view execution timed out`. Raise the timeout if your views legitimately take longer, and make
  sure views observe their context so the deadline can stop them.
- Only `CallView` is accepted. `InitiateView` is rejected.
- `PUT /v1/Views/{View}` and `GET /v1/Views/Stream/{View}` are removed. With `web` in `backends`,
  `fsc.web` serves `POST /v1/ViewService/ProcessCommand` and the WebSocket
  `GET /v1/ViewService/StreamCommand`, carrying the same signed commands as gRPC as protojson
  (see [view-service-http.md](../platform/view/services/view-service-http.md)). Unsigned
  requests are rejected. Clients should use the FSC view client
  (`platform/view/services/view/client`), which supports both transports.
- The view routes no longer require a TLS client certificate; the command signature
  authenticates the caller. Set `fsc.web.tls.clientAuthRequired: true` to demand one anyway.
- A command accepted on one transport counts as a replay on the other.
- Request bodies over 10 MiB get `413 request too large`.

Startup fails, naming the key, on:

- `fsc.grpc.enabled: true` without `fsc.view.remote` (nothing else uses the gRPC listener, so
  disable it or add the block);
- any `fsc.view.remote` key other than `enabled` while `enabled` is not `true`, or an unknown key;
- empty, duplicate or unknown `backends`, or a listed backend whose listener is disabled;
- an invalid `timeWindow`, `maxMessageSize` or `clients` entry;
- `fsc.web.enabled: true` without a valid `host:port` in `fsc.web.address`, or a missing or
  malformed `fsc.grpc.address`.

String lists accept a comma-separated value, so the whole block can be set from the
environment, for example `CORE_FSC_VIEW_REMOTE_BACKENDS=grpc,web`.

On the gRPC listener, with `clientRootCAs` set and `clientAuthRequired: false`, a client
certificate that the client offers is verified against those roots, and the client must put its
hash in the command's `tlsCertHash` (the FSC view client does this). Without `clientRootCAs`, the
listener does not request a client certificate.

## TLS configuration

**Applies to:** Every node, Fabric and Fabric-x, and Fabric-x only, per row below.

All TLS settings share one schema: nested `{file:}` / `{files:}` values, plural CA lists, and
field-by-field inheritance from a parent `tls:` block. The reference is in
[configuration.md](../configuration.md#migrating-tls-configuration). Old keys fail startup; they
are not translated, so a stale configuration cannot fall back to plaintext without saying so.

| --- | --- | --- |

| `fsc.metrics.prometheus.tls` | `fsc.metrics.clientAuthRequired` | Every node |
| `fabric.<net>.tls.clientAuthRequired` | `fabric.<net>.tls.clientAuthEnabled` | Fabric and Fabric-x |
| `fabric.<net>.tls.serverHostOverride` | `fabric.<net>.tls.serverNameOverride` | Fabric and Fabric-x |
| `fabric.<net>.tls.rootCert.file`, `fabric.<net>.tls.rootCertFile` | `fabric.<net>.tls.rootCAs.files` | Fabric and Fabric-x |
| `fabric.<net>.tls.cert`, `.key`, `.clientRootCAs` | none; delete them (a network only dials out) | Fabric and Fabric-x |
| `fabric.<net>.ordering.tlsEnabled` | `fabric.<net>.tls.enabled` | Fabric and Fabric-x |
| `fabric.<net>.ordering.tlsClientAuthRequired` | `fabric.<net>.tls.clientAuthEnabled` | Fabric and Fabric-x |
| `orderers[].tlsEnabled`, `peers[].tlsEnabled` | `…[].tls.enabled` | Fabric and Fabric-x |
| `orderers[].tlsDisabled`, `peers[].tlsDisabled` | `…[].tls.enabled: false` | Fabric and Fabric-x |
| `orderers[].tlsClientSideAuth`, `peers[].tlsClientSideAuth` | `…[].tls.clientAuthEnabled` | Fabric and Fabric-x |

| `orderers[].tlsRootCertBytes`, `peers[].tlsRootCertBytes` | none; delete them | Fabric and Fabric-x |
| `queryService` / `notificationService` `tls.clientKey`, `tls.clientCert` (flat path strings) | `tls.clientKey.file`, `tls.clientCert.file` | Fabric-x only |
| `queryService` / `notificationService` `tls.rootCerts` (flat list) | `tls.rootCAs.files` | Fabric-x only |

Behaviour changes in the same area:

| Change | Platform |
| --- | --- |
| `fsc.tls` is a block of shared server-side defaults. `fsc.grpc.tls` and `fsc.web.tls` inherit from it field by field, so the certificate and key can be set once. | Every node |
| All listeners and clients use one cipher-suite list (ECDHE with AES-GCM or ChaCha20). Clients that can only negotiate static-RSA suites fail the handshake with the gRPC listener. | Every node |
| Websocket P2P clients require TLS 1.3, like the websocket server already did. | Every node |
| `ordering.tlsEnabled` and `ordering.tlsClientAuthRequired` used to override the network's TLS settings for orderer connections only. The network `tls:` block now applies to every connection. To reach an orderer in plaintext, give it a per-orderer `tls: {enabled: false}`. | Fabric and Fabric-x |
| CA files configured for orderers and peers are added to the CAs from the channel configuration instead of replacing them. | Fabric and Fabric-x |
| Query and notification endpoints require TLS 1.3 by default. | Fabric-x only |

New optional keys, no default change when absent:

- `minVersion` / `maxVersion` in any `tls:` block (`771` = TLS 1.2, `772` = TLS 1.3). All
  platforms.
- `maxRecvMsgSize` / `maxSendMsgSize` (unset or `0` means 100 MiB) on `fsc.grpc` (every node),
  on Fabric peers and orderers (Fabric and Fabric-x), and on the query and notification endpoints
  (Fabric-x only). Raise the latter if large Fabric-x query results fail with `ResourceExhausted`.

## Monitoring and operations endpoints

**Applies to:** Every node, except the metrics marked otherwise.

- `fsc.metrics.clientAuthRequired` defaults to `true`, so `/metrics` and `/logspec` require a
  verified client certificate. On a listener that never requests one (TLS disabled or no
  `clientRootCAs`) the node starts, logs a warning, and the endpoints reject every request; an
  explicit `true` there fails startup. Set `false` to keep serving a scraper without a
  certificate, preferably on a dedicated, network-restricted `fsc.metrics.address`.
- `fsc.metrics.address` gives `/metrics` and `/logspec` their own listener with its own
  `fsc.metrics.tls`. Without it they stay on `fsc.web`.
- `fsc.web` serves `GET /healthz` (liveness; never checks peers or orderers) and `GET /readyz`
  (readiness; 503 with a JSON list of unready components). Both skip the client-certificate
  check of the view routes.
- With tracing enabled and no sampling ratio, FSC samples every trace (`ratio: 1`). An unknown
  `fsc.tracing.provider` or a ratio outside `[0, 1]` fails startup.

Metrics to update in dashboards and alerts:

| Metric | Change | Platform |
| --- | --- | --- |
| `fsc_view_services_view_grpc_client_*` | renamed `fsc_view_services_view_client_*` | Every node |
| `fsc_view_services_view_grpc_server_view_handler` | removed | Every node |
| `requests_rejected` (view service, labelled `stale` or `replay`) | new | Every node |
| `fsc_database_*` (Postgres pools) | new | Every node |
| `fsc_view_services_comm_stream_read_errors` | new | Every node |
| `fsc_connection_state` and `fsc_connection_*`, orderer broadcasters | new | Fabric and Fabric-x |
| `fsc_connection_state` and `fsc_connection_*`, block delivery per peer | new | Fabric only |
| `fsc_fabric_core_generic_committer_commit_failures` | new | Fabric only |

The catalog is in [monitoring_metrics.md](../platform/view/services/monitoring_metrics.md).

## P2P and sessions

**Applies to:** Every node.

- `fsc.p2p.maxRecvMsgSize` and `fsc.p2p.maxSendMsgSize` (default 10 MiB) limit P2P messages, and
  the websocket transport honours them. They cannot be disabled: `0` or a negative value selects
  the default. Set a size large enough for your payloads, and the same on every node.
- Each remote peer may run at most `fsc.p2p.maxRespondersPerPeer` responders at once (default
  `1000`). Further first messages get an error reply.
- A session whose message queue is full drops the message, counts it, and closes the session. A
  slow consumer no longer stalls dispatch for the whole node.
- Websocket clients check that the server's TLS certificate belongs to the peer ID they dialed
  and fail with `peer identity binding failed` otherwise. Every
  `fsc.endpoint.resolvers[].identity` must be the remote node's actual `fsc.identity`.
- The websocket server stops trusting an extra CA once it has been withdrawn.
- Incoming sessions that name an initiator context are rejected.

## Shared network settings

**Applies to:** Fabric and Fabric-x. Both platforms read these keys from `fabric.<network>`.

- `fabric.<net>.keepalive.time` turns on client keepalive pings, and
  `keepalive.connectionTimeout` and per-peer/orderer `connectionTimeout` are honoured. Nodes
  that already set these keys start using them.
- Opening a channel that `fabric.<net>.channels` does not list returns an error.
- A network can be added at runtime through `Config.AddNetwork` (see
  [Fabric and Fabric-x API](#fabric-and-fabric-x-api)).
- PKCS11 `SessionCacheSize` in an MSP's BCCSP options is configurable (default `10`).
- Invalid `mspCacheSize` and `ordering.connectionPoolSize` values fail startup (see
  [the table below](#other-configuration-that-now-fails-startup)).

## Fabric

**Applies to:** Fabric only.

- Peers returned by discovery are validated against the channel's MSPs, and their TLS roots come
  from the channel configuration. Peers that fail validation are dropped with a warning, so an
  endorsement that only such peers could satisfy now fails.
- `committer.pollingTimeout` is read from the channel configuration (default `100ms`; v0.13
  always used `1s`).
- Delete `delivery.waitForEventTimeout` (never used) and the chaincode `private` key (no longer
  read).
- Block delivery reconnects with exponential, jittered backoff starting from
  `delivery.sleepAfterFailure`, capped at one minute.

A block that fails to commit no longer stops the channel's block stream on the first error.
Transient database errors are retried with `committer.retries` (default `5`) and
`committer.retrySleep` (default `10s`) under `fabric.<net>.channels[]`. When retries run out, or
the failure is deterministic, the channel's block stream stops until the node restarts and
`commit_failures` is incremented. Alert on that counter.

## Fabric-x

**Applies to:** Fabric-x only.

- fabric-x-committer v1.0.7 or later is required. The finality and ledger services dial the
  committer's `SidecarService`, which older committers do not serve.
- Transactions identify X.509 creators by certificate ID (the SHA-256 of the DER certificate)
  instead of embedding the certificate. The committer resolves the ID through the known
  certificates in the channel configuration, so add each FSC node's signing certificate there,
  for example with `fxadmin modify app known-certs add`. Idemix identities are sent unchanged.
- The vault no longer keeps RWSets and transaction statuses; status comes from the committer's
  query service.
- New optional keys under `notificationService`: `handlerTimeout` (`5s`), `listenerTTL` (`2m`,
  `0` disables the local backstop), `sweepInterval` (`30s`), `handlerWorkers` (`16`) and
  `handlerQueueSize` (`1000`). See [Fabric-x configuration](../platform/fabric-x/configuration.md).
- A non-positive `queryService.requestTimeout` falls back to the default.
- The notification stream reconnects with backoff after a committer restart and keeps pending
  finality listeners.

## Other configuration that now fails startup

| Configuration | What to do | Platform |
| --- | --- | --- |
| Keys that differ only in case, or a dotted key that repeats a nested key | Keep one spelling | Every node |
| A `core.yaml` that cannot be read or parsed (FSC no longer tries the next search location) | Fix the file or its path | Every node |
| A dotted key colliding with a `CORE_` environment variable | Set the value in one place | Every node |
| `fsc.id` unset | Set it | Every node |
| An unknown `fsc.identity.type` | Fix the value | Every node |
| An endpoint resolver without `name` or `identity.path` | Add the missing field | Every node |
| A resolver address key other than `Listen`, `View` or `P2P`, or two keys for one port | Use only those three | Every node |
| A store referencing an undefined persistence, `persistence: default` without a default block, or a persistence without `type` | Define the persistence; older versions fell back to memory and lost data on restart | Every node |
| `fsc.kvs.cache.size` below 1 | Use at least `1` | Every node |
| `fabric.<net>.mspCacheSize` not an integer `>= 0` | Fix the value (`0` disables the cache) | Fabric and Fabric-x |

| A negative `channels[].finality.eventQueueWorkers` | Use `0` or more | Fabric only |

# For developers

Most changes below are compile errors. Behaviour-only changes are called out.

Fabric-x applications use the `platform/fabric` service API (network, channel, endorser, state)
as well, so sections marked **Fabric and Fabric-x** apply to them too.

## Contexts

**Applies to:** Every node, with Fabric-only items marked.

Every API that starts work or blocks takes a `context.Context`, and background goroutines stop
when their context is cancelled.

- `view.Session` has `Send(ctx, payload)` and `SendError(ctx, payload)`. `SendWithContext` and
  `SendErrorWithContext` are removed; rename calls and add the context to old `Send` calls.
- `RunView` in `platform/view/services/view` takes a leading `context.Context`.
  `view.WithGoContext` is a new `RunViewOption`.
- `NewBatchExecutor`, `NewBatchRunner`, `NewTimeoutCache`, `NewTimeoutEviction`,
  `NewListenerManager`, `NewSequentialListenerManager` and `NewManager` take a leading
  `context.Context`. The batcher returns `ctx.Err()` on cancellation, and `Notifier.Subscribe`
  fails once the notifier is closed.
- Fabric only: `NewDeliveryFLM` and `NewChaincode` take a leading `context.Context`, and the
  Fabric finality `IsFinal` methods take a `context.Context`.

## Errors instead of panics

**Applies to:** Every node, Fabric and Fabric-x, and Fabric-x only, as marked.

Several APIs that panicked on bad input or an uninitialized component return an error. Callers
must check it.

- Fabric and Fabric-x: `endorser.NewBuilder` returns `(*Builder, error)`;
  `NewBuilderWithServiceProvider` is removed.
- Fabric and Fabric-x: `(*endorser.Transaction).Namespaces` and `(*state.Namespace).NumInputs`,
  `NumOutputs`, `Commands`, `Outputs` and `Inputs` return `(T, error)`.
- Fabric and Fabric-x: `GetMSPIDs` and `IsIdemixMSP` on `driver.ChannelMembership` and
  `fabric.MSPManager` return an error alongside the result, so an unloaded channel configuration
  is distinguishable from an empty answer. `FabricMSPManager` is removed.
- Fabric-x only: `ledger.Provider.Context` returns `(context.Context, error)`, and
  `ledger.Provider.NewLedger` and `finality.Provider.NewManager` return an error wrapping
  `driver.ErrNotInitialized` before startup completes.
- Every node: `websocket.Config.ClientTLSConfig` and `ServerTLSConfig` return
  `(*tls.Config, error)`, and `websocket.NewHost` returns `(*host, error)`. `ClientTLSConfig`
  takes no arguments.
- Every node: `(*TableNameCreator).MustGetTableName` is removed; use `CreateTableName`.

## Views, sessions and communication

**Applies to:** Every node.

- `view.SessionInfo.Endpoint` and `EndpointPKID` are renamed `RemoteEndpoint` and `RemotePKID`.
  `LocalPKID` is new.
- `p2p.NewService` takes a `ConfigService` (nil selects the default). `p2p.CommLayer` gains
  `ReplyError` and `DeleteSession`. `p2p.ViewManager` drops `DeleteContext`.
  `SessionFactory.DeleteSessions(ctx, id)` is `DeleteSession(ctx, id, pkid)`, and
  `Sessions.GetSessionIDs` is `GetSessionInfos`.
- `Manager.NewResponderContext` returns a release func in place of `isNew`, and returns
  `ErrNotResponderContext` for an initiator context ID and `ErrInvalidSessionID` for an empty
  session ID.
- `DefaultEnqueueTimeout`, `DefaultDispatcherTimeout` and `NetworkStreamSession.SetEnqueueTimeout`
  are removed.
- `routing.NewResolvedStaticIDRouter`, `ResolvedStaticIDRouter`, `LabelResolver`, `LabelRouter`
  and `AlwaysLast` are removed. Use `NewEndpointServiceIDRouter` or `StaticIDRouter`, and
  `AlwaysFirst`, `RoundRobin` or `Random`.
- `AddResolver` and `UpdateResolver` return an error for address keys other than `Listen`, `View`
  and `P2P` and for repeated keys. `ResolverInfo.AddressList` is removed; use `Addresses`.
- `GetIdentity` no longer matches an empty label. Callers holding a verified pkID pass an empty
  label.
- `session.NewFromInitiator(viewCtx, party)` is removed; use
  `session.NewJSON(viewCtx, viewCtx.Initiator(), party)`. `io.Comm` is removed.
- `endpoint.NetworkMember` is removed; use `endpoint.Resolver`. `events.EventService` and
  `events.Service` are removed; inject `events.Publisher`, `events.Subscriber` or
  `events.EventSystem`.
- `(*id.Provider).Admins()` and `server.IdentityProvider.Admins()` are removed; use `Clients()`.
- `NewVarintProtoReader` and `NewVarintProtoWriter` take a maximum message size.

## View client and SDK servers

**Applies to:** Every node.

- The view client is `platform/view/services/view/client`;
  `platform/view/services/view/grpc/client` is gone. `NewClient` returns `*client.Client`, and
  `Config.Transport` selects gRPC (default) or HTTP. `ViewServiceClient` and
  `ViewServiceClientImpl` are replaced by `Transport`. `Initiate` is removed. The client rejects a
  response whose header does not name the hash of its command.
- `web/client.Config` takes PEM in `TLSCertRaw` / `TLSKeyRaw`; `TLSCertPath` / `TLSKeyPath` are
  removed.
- `web.InstallViewHandler` is replaced by `NewProcessCommandHandler` and `NewStreamCommandHandler`.
  `web/server.HttpHandler`, `ReqContext`, `RequestHandler`, `WSStream`, `server.Config` and the
  `platform/view/services/web` message package are removed.
- `server.InstallViewHandler` takes the remote timeout in place of a `tracing.Provider`.
  `server.NewViewServiceServer` takes a time window. `grpc.NewBindingInspector`,
  `BindingInspector` and `CertHashExtractor` are removed.
- Listeners are the `WebServer` and `GRPCServer` interfaces, built by `WebServerConstructor` and
  `GRPCServerConstructor`. To replace a listener, decorate its constructor in dig; the SDK calls
  it only when the listener is enabled. Transports are `Backend`s in the `view-remote-backends`
  dig group.
- `sdk.Server` is renamed `sdk.WebServer`, and `ops.Server` is `ops.WebServer`.
  `NewOperationsServer` takes a `WebServer`, and `Serve` takes a `GRPCServer` and a `WebServer`.
  `sdk.NewWebServer` takes only the configuration service and mounts no routes.
  `sdk.NewViewServiceServer` takes a `RemoteConfig` first and no `*grpc.GRPCServer`.
  `sdk.CommandTimeWindowKey` is removed.
- `config.Provider.GetStringSlice` splits a single string value on commas.

## Storage

**Applies to:** Every node, except the vault items marked Fabric only.

- The SQL stores use an internal statement builder. `pagination.ApplyToSquirrel`, the SQLite and
  Postgres `NewConditionInterpreter` / `NewPaginationInterpreter`, and the `sq.PlaceholderFormat`
  parameter of the store constructors are removed.
- `SQLError`, `VersionedPersistence`, `UnversionedWriteTransaction` and `QueryUnique` are removed
  from the view storage driver; use `QueryUniqueContext`.
- Fabric only: `common.NewVaultStore` takes a `KeyEncoder` in place of a sanitizer.
  `sql.Sanitizer`, the Postgres and SQLite `NewSanitizer` and the common `Sanitizer` wrapper are
  removed.
- Fabric only: `sqlite.NewDriver` and `postgres.NewDriver` in
  `platform/fabric/services/db/driver/sql` are removed. Use
  `sqlite.NewDriverWithDbProvider(cfg, sqlite2.NewDbProvider())` and
  `postgres.NewDriverWithDbProvider(cfg, postgres2.NewDbProvider())`, where `sqlite2` and
  `postgres2` are the packages under `platform/view/services/storage/driver/sql`. The fabric
  `TracingConfig` is `platform/view/services/storage/driver/sql/common.TracingConfig`.
- Fabric only: `platform/fabric/services/db/driver/sql/common` no longer exports `ToBytes`,
  `FromBytes` or the `TTest*` test tables.

## Endorsement and transactions

**Applies to:** Fabric and Fabric-x, with Fabric-only items marked.

- `driver.RWSet` in `platform/common/driver` gains `GetReadVersion(ns, key) (RawVersion, error)`.
  Implementations and mocks must add it.
- `endorser.Transaction.HasBeenEndorsedBy` returns an error with no parties, and for a party
  whose proposal response endorses another payload or whose signature does not verify. It does
  not consult providers passed to the collect view's `SetVerifierProviders`; register those with
  `Transaction.AppendVerifierProvider` as well.
- `SetFromEnvelopeBytes` rejects an envelope whose proposal hash does not match the endorsed one.
- `SetFromBytes` rejects a transaction with proposal responses but no signed proposal, or a
  response that does not endorse its signed proposal (Fabric) or transaction ID (Fabric-x). A
  flow that collects endorsements from remote parties before endorsing locally must call
  `EndorseProposal` first.
- `state.EndorseTransaction`, `state.Bytes`, `state.QueryIteratorInterface` and
  `state.CommonIteratorInterface` are removed. Use `any` or `*endorser.Transaction`, and `[]byte`.
- Fields tagged `state:"hash"` must be hashable; other types are rejected.
- Fabric only: `IsPrivate` is removed from `fabric.Chaincode`, `driver.Chaincode`,
  `driver.ChaincodeConfig` and `services/chaincode.Chaincode`.

## Fabric and Fabric-x API

**Applies to:** Fabric and Fabric-x. These packages live under `platform/fabric` and the Fabric-x
driver builds on them.

- `Config.AddNetwork(raw, validators...)` adds a network at runtime. To support it, `NewConfig`,
  `NewCore` and `NewProvider` take a `DynamicConfigProvider` / `DynamicConfigService`, and
  `NewFabricNetworkServiceProvider` also takes a `[]NetworkConfigValidator`, filled from the
  `fabric-network-config-validators` dig group.
- `driver.ConfigService.NewDefaultChannelConfig` is removed.
- `delivery.New` and `delivery.NewService` take a `*connstate.Metrics` (nil reports nothing) and
  no `waitForEventTimeout`. `config.Delivery.WaitForEventTimeout` is removed.
  `delivery.NewMetrics` takes the network and channel names.
- `generic/driver.NewProvider` and `fabricx.NewProvider` take a `*connstate.Metrics` third. The
  dig inputs of the fabric and Fabric-x `NewDriver` and `NewChannelProvider` gain a `ConnState`
  field, provided by the view SDK.
- The driver aliases `Resolver`, `RWSExtractor` and `GetFabricManagementService` and four
  `common/driver` aliases are removed; get the network provider through dig.
- `Network`, `Endpoint`, `Vault`, `VaultPersistence`, `VaultOpts`, `TLS`, `File` and `Files` are
  removed from `platform/fabric/core/generic/config`. Seven TLS accessors collapse into
  `NetworkClientTLS()`. Read network configuration through `config.Service`.
- The vendored `channelconfig` package drops unused exports (`Resources`, `ChannelValues`,
  `ConfigValue`, `Channel`, `ValidateCapabilities`, the `*Value` builders and others).
- `grpc.CredentialSupport` is removed. Dial with `grpc.NewGRPCClient` and `ClientConfig`, or use
  `SecureOptions.TLSConfig()` with `credentials.NewTLS`.
- `idemix.NewProviderWithStandardPolicy` is removed; use
  `NewProviderWithSigType(conf, kvs, sp, bccsp.Standard)`.
  `Deserializer.DeserializeVerifierAgainstNymEID` is removed; call
  `DeserializeAgainstNymEID(raw, true, nymEID)` and build a `NymSignatureVerifier` from the
  returned `NymPublicKey`.
- Fabric only: `MembershipConstructor` returns `*membership.Service`.

## Fabric-x API

**Applies to:** Fabric-x only.

- `ledger.New` in `platform/fabricx/core/ledger` takes a `committerpb.SidecarServiceClient` in
  place of a `BlockQueryServiceClient`. Regenerate mocks of the finality and ledger clients.
- The query service gains `GetNamespacePolicies` and `GetTransactionStatuses`; implementations
  and fakes must add them.
- `vault.NewVault` takes a `MetadataService`. The vault no longer exposes `SetDiscarded`,
  `Statuses`, `DiscardTx`, `CommitTX`, `RWSExists`, `Match` or the `Marshaller` type.
- The state service resolves a `Certifier` per network. Fabric-x registers
  `TrustedReadCertifier`; Fabric keeps `ChaincodeCertifier`.
- The `rwset.Loader` rejects envelopes whose header type is not `HeaderType_MESSAGE`, or whose
  channel header names another channel or transaction ID. `AddHandlerProvider` is a no-op.
- `RegisterTransactionHandler` and `NewHandler` in `platform/fabricx/core/committer`, and
  `P2PCommunicationType` and `WebSocket` in `platform/fabricx/sdk/dig`, are removed.

## Metrics, tracing and logging

**Applies to:** Every node.

- `metrics.GetProvider` is removed; inject `metrics.Provider` through dig.
- `tracing.NewProvider` and `NewProviderWithNodeName` are removed; compose
  `NewProviderFromConfigService` with `NewProviderWithBackingProvider`. Use
  `go.opentelemetry.io/otel/trace.WithTimestamp` and `go.opentelemetry.io/otel/attribute.Int` in
  place of `tracing.WithTimestamp` and `tracing.Int`.
- Context-aware log calls can attach context values as fields, configured with
  `logging.Init(Config{ContextLogFields: ...})` or `RegisterContextLogField`. `logging.Named` is
  removed.

## Integration test harness (`nwo`)

**Applies to:** Every node, with platform-specific items marked.

- Every FSC node, peer and orderer runs as its own ifrit process, named `<prefix>.orderer.<name>`
  and `<prefix>.peer.<name>`. `NWO.KillFSC`, `NWO.FSCProcesses`, `NWO.TerminationSignal`, the
  `Group` interface, `OrdererGroupRunner` and `PeerGroupRunner` are removed. Use `KillFSCNode`,
  `StopPeer` / `StartPeer` and `StopOrderer` / `StartOrderer`.
- `api.GRPCClient` is renamed `api.RemoteViewClient`, and `api.WebClient.StreamCallView` returns
  `*client.Stream`. The web client calls views over the HTTP binding, signed as the node's
  `fsc.identity`.
- Node metrics are read through a client built from the node's connection configuration.
- Fabric only: `topology.PrivateChaincode` and `ChannelChaincode.PrivateChaincode` / `Private`
  are removed.
- Fabric-x only: the tests need fabric-x tools v1.0.3 or later (`make install-fabricx-tools`).
